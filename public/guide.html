How Memory Atlas works

← back to the lab

The idea

"Agent memory" is not one store — it is four substrates with different lifecycles and different sources of truth. Memory Atlas seeds all four for a fictional payments service, then lets you ask five questions and watch two recall strategies disagree.

  • Chat Memory (episodic) — dialogue claims. Session-scoped, decays over turns, lowest authority.
  • Skill (procedural) — candidate procedures distilled from runs; recallable only after enough successes.
  • LLM-Wiki (semantic) — curated, citable knowledge like runbooks and ownership.
  • Code-Graph (structural) — facts extracted from the repo itself (deploy.yaml, lockfiles, source imports). Highest authority for "what is true now".

The bug: flat recall

Flat recall ranks every stored claim by recency and confidence. In the seeded scenario a user recently repeated an outdated habit ("ship to eu-west-1") — so flat recall answers a structural question from an episodic substrate and gets it wrong. The same happens for the datastore ("we're moving to Postgres" vs. the better-sqlite3 import still in the code) and for an unproven one-run "skill".

The fix: governed recall

  • Routing — each question kind has a source of truth: structural → code-graph, semantic → wiki, procedural → skill, episodic → chat.
  • TTL — episodic entries expire after chatTtlTurns idle turns.
  • Scope — chat from other sessions does not leak into this one.
  • Promotion — a candidate skill is recallable only after skillMinRuns successes.
  • Provenance — every entry carries evidence (file:line, runbook version, run ids) so answers drill down to ground truth.

Note the asymmetry: governed recall still answers the standup question from chat — episodic memory is the right substrate for episodic questions. The discipline is routing, not distrust.

Run it

  • npm start — serve this lab (PORT env, default 3000)
  • npm run report — CLI side-by-side from the disk fixtures in examples/
  • npm test — node:test suite (memory semantics, code-graph extraction, scenario, server, fixture parity)
  • npm run check — tests + report, used by render.yaml

Honest limits

This is a toy: routing is a static table, extraction is regex over four fixture files, and "turns" are integers not wall-clock time. Real systems (e.g. TencentDB Agent Memory) add embeddings, hybrid retrieval, and layered L0→L3 compaction — but the failure mode reproduced here is real: any recall path that ignores which substrate a fact came from will eventually serve a stale fact with full confidence.
